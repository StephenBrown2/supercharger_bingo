Done. DatabaseService keeps only db and initialize(database:). Passing a database replaces the current one, which is how tests swap it. Rejected: no module. The bugs it hid were fixed in the screens. Both modules would have had one caller each. Delete already had five widget tests, and the name lookup is one cached query per Site. A deletion test found that the complexity would only move, not disappear. The grilling found real defects instead. Reset Database and Clear Local Data deleted Pending Visits, which on web is all the user's data. The open map never heard about Visit writes, so its count went stale after a delete, an import or a reset. And Sync Visit History was a TODO stub.

Changes. AppDatabase.resetKeepingPending() wipes everything that can be downloaded again but keeps Pending Visits, their outbox entries and their Sites, and returns how many it kept; Reset Database uses it and says the count. CheckinOutbox.remove became discard, which returns Discard.discarded, confirmed, busy or notPending. A Visit this engine is sending is discarded only if the send fails. If supercharging.life accepts it, it stays Confirmed and the user is told which one. The mark lives in memory, so killing the app cancels the discard. A new Settings tile, Discard Pending check-ins (N), uses the same rule. The map reloads on Drift table updates to visits, debounced by 300 ms. Clear Local Data (Android's Clear data covers it) and the Sync Visit History stub are gone. The Visits screen says Discard for Pending Visits and Delete for Confirmed ones.

Glossary: Confirmed (with the delete rule, using supercharging.life's own word, "Delete This Checkin") and Discard.

Closing summary

All six candidates are settled

Done: the Check-in outbox (1), the First module (2), the Session module (4) and the DatabaseService dissolution (5). Rejected: the Site query module (3), because reading EXPANDING as OPEN removed its cause, and Visit history and data maintenance (6), because single-caller modules would only move code. Candidate 6's real bugs were fixed instead: Pending Visits now survive a reset, discard follows one rule, and the map follows Visit writes.

Still open: flattening the database migrations (schema v23), with an ADR, agreed under candidate 1. Also open: in-car checks on Intel and AMD Tesla browsers, live supercharging.life sign-in flows on device, and Visit writes made by the Live Update engine, which reach the main map only when it reloads.
